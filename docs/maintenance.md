# 维护与验证

## 单一事实来源

- 用户使用与安装说明在 [README](../README.md)。
- Agent 的任务行为以 [SKILL.md](../SKILL.md) 为准；细节按入口路由读取四份参考。
- 文献 ID 与阅读深度只在 [证据索引](../references/evidence.md) 定义；其余文件引用 ID，不复制第二套书目。
- 仓库规则在 [CLAUDE.md](../CLAUDE.md)；`AGENTS.md` 是指向它的相对符号链接。
- 自动生成的 Agent 记忆不作为仓库文档，也不上传会话记录、身体数据或内部测试答复。

## 本地验证

在仓库根目录运行，使用 Python 3.11 或更高版本：

```console
python -m pip install -r requirements-dev.txt
python scripts/validate_repository.py
python -m unittest discover -s tests -v
```

验证器检查六个技能文件、UTF-8、YAML 元数据、Markdown 相对文件链接、32 个不重复来源 ID 及引用是否可解析、文档完整性、规则同源和明显的本地路径／凭据泄漏。单元测试通过损坏副本检验：丢文件、坏链接、未知或重复文献 ID、失效默认提示词、规则分叉和路径泄漏应被拒绝。

Windows 的 Git 在禁用符号链接时可能把 `AGENTS.md` 检出为仅含 `CLAUDE.md` 的指针文件；验证器仅在 Windows 接受这种形式。远端 Git 树仍须记录为 `120000` 符号链接；Linux CI 要求真正的相对符号链接。支持符号链接的客户端直接读取同一份规则。

## CI 与提交

[Skill validation 工作流](../.github/workflows/validate.yml) 对 push 和 pull request 运行相同命令，使用 Python 3.11／3.13；仅需仓库只读权限，不需要 API 密钥或运动员资料。CI 运行不访问文献网站，避免将网络故障当成技能内容失败。

1. 在分支修改相应事实来源，检查 README 与参考之间是否矛盾。
2. 运行本地验证与负例测试；涉及行为变化时，另做下表的实际答复验收。
3. 提交 PR，检查该 PR 最新提交对应的 CI，失败则修复后重跑。
4. 未看到成功的运行结果，不把“工作流已提交”写成“CI 已通过”。

## 回答行为验收

以下是任务级验收标准，不含个人档案，也不作为固定课表。用修改后的技能实际回答，并记录问题数量、可执行性和计算结果。

| 请求 | 验收重点 |
|---|---|
| 两小时轻松骑行怎么补给 | 直接给可执行的 g/h 与携带方案，不追问体重、FTP或外卖 |
| 休息日蛋白粉有没有必要，只问原则 | 先解释每日总量与补缺口，不要求食谱或体重 |
| 想提升 FTP，安排下周；无其他背景 | 最多问近期稳定周量与下周可用时间，同时给可用的过渡建议，不编个人基线 |
| 按给定 g/kg 换算个人蛋白克数，但未给体重 | 只补问体重，先保留公式，不编数值 |
| 已给目标、周量、频次、恢复和测量条件 | 直接安排课次，核对总时长、恢复和补给，不再发画像问卷 |
| 无功率的 XCO，或 Enduro／DH 握持疲劳 | 不由模拟功率设 FTP；识别技术与局部疲劳负担，不套同距离公路模板 |

2026-10-12初版与提问体验修订曾完成实际答复检查；内部原始答复不随仓库发布。这是历史验收记录，不代表每次 CI 重新运行了语言模型。**静态 CI 不能证明 Agent 一定遵守规则，也不能验证训练效果、医学正确性或外部来源仍可访问。** 训练与营养的新主张、补剂剂量或特殊人群应用仍须按技能规则查当前依据。
